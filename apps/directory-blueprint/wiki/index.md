## Scripts
- `scripts/fetch_dataforseo.py`: Gate 1 listings pull from the DataForSEO Business Listings API into the Outscraper layout. `--find-category pool` (free) lists category ids; `--category swimming_pool_contractor --state Florida --state-code FL --estimate` quotes rows and cost in three requests (about five cents), reports the primary-category count and the website share, and prints a `VERTICAL FLAG` only under 100 primary-category businesses or under half with a website; drop `--estimate` to pull. Login read from Claude Code's settings (`~/.claude.json`), the environment, or a Claude Desktop stdio entry; never a file in this folder.
- `scripts/connect_dataforseo.py`: run by the member in their own Terminal, never by Claude. Asks for the API login and password (hidden), tests them with DataForSEO, saves them with `claude mcp add -s user dataforseo` wherever `claude` is installed. `--check` says whether a working login is saved, without printing it. The default DataForSEO instruction since 2026-10-01.
- `scripts/check_vertical.py`: Gate 1, on request only. `--category <id> --state <State>` prints one card: category exists, size against 200 to 5,000, primary-category share, website share; about five cents (`--quote`). No search results, volumes or difficulty. Never run on a member who has chosen a vertical and did not ask ([[gate-1-intake]]).
- `scripts/clean_listings.py`: Gate 2, either source. Also strips Maps tracking parameters from `website` (they arrive percent-encoded into the path and 404) and transliterates accented letters in `slug` and `city_slug` (Cañon City is `canon-city`). `python3 scripts/clean_listings.py input/listings-raw.csv --niche "pool builder,pool construction,custom pools" --category "swimming pool contractor" --state FL --out output/<slug>/02-listings-clean.csv` (a broad term like `pool` alone lets cleaners and supply stores in; `--niche` or `--category` may be given alone). The report lists kept rows by primary type and the rows kept only by the category fallback; nothing is dropped for its trade, Gate 4 decides.
- `scripts/fetch_sites.py`: Gate 3, when the export has no text. `python3 scripts/fetch_sites.py output/<slug>/02-listings-clean.csv --cache output/<slug>/03-cache/sites` reads each listing's own website (home plus up to three pages). Free, cached, standard library only, `--retry-failed` to read failures again, `--want "term|term"` adds the vertical's own inner-page words. Ends with one summary line by status (readable, no website, blocked, dead, script-rendered, other) for the Gate 3 report.
- `scripts/build_evidence.py`: Gate 3. Turns the site cache into per-city evidence packets (two quotes per attribute at most) with `--patterns output/<slug>/03-attributes.json` (the per-vertical file, a `pattern` per attribute), and prints the token estimate the cost gate needs.
- `scripts/make_batches.py`: Gate 3. Cuts the evidence into readable batches, skipping listings already answered (`--start N` to number new batches after existing ones); `--attributes 03-attributes.json` prints the vertical's attribute table (key, true when, core work) at the top of every batch.
- `scripts/enrichment-instructions.md`: Gate 3. The general rules every batch is answered under, any vertical: what counts as evidence, the description rules, two worked examples (labelled as one run's). The vertical's attributes come from the batch's own table.
- `scripts/examples/`: one labelled example of the per-vertical attribute file (`attributes-pool-builders.json`, with `true_when`, `pattern` and `core`) and a README on the shape. Never a recommendation of a vertical.
- `scripts/run_batches.py`: Gates 3 and 5. Writes `TASK.md` and `check-batch.sh` into the directory's cache folder, then starts one headless Claude Code run per batch (`claude -p`), a few at a time, checks each result and reruns a failing batch with the checker's lines. `enrich --slug <slug>` and `city-copy --slug <slug> --niche "<niche plural>"`; `--status`, `--dry-run`, `--only <num>`, `--model` (Sonnet by default, about 4 cents a listing against 16 on the account's default model, measured 2026-09-30). Holds `runner.lock` in the cache folder so a second runner refuses, prints one summary line (batches, listings, cost, cents a listing, wall time) for the report, and writes `<cache>/review.md`, the latest reply of every batch (the runners' notes on unsure answers and flagged copy), to read before the gate is approved. The documented path when there are no subagents.
- `scripts/merge_enriched.py`: Gate 3. Checks every answer and writes `03-listings-enriched.csv` only when nothing fails; `--only` and `--slugs` check one batch. Description openers are tallied across every batch in the cache; an opener four or more listings share fails those listings (only the checked batch's own under `--only`), and the full merge names the batches to rerun.
- `scripts/clean_descriptions.py`: Gate 3. Takes internal wording ("the packet", error codes) out of the descriptions in the enrichment cache.
- `scripts/apply_exclusions.py`: Gate 5. Copies the enriched listings into the site and applies `04-exclusions.csv` (drop, blank_website).
- `scripts/add_socials.py`: Gate 5, optional, after `apply_exclusions.py`. Writes the profile links `fetch_sites.py` found (or `fetch_sites.py --socials` adds to an existing cache) into `site/src/data/listings.csv` as a `socials` column; the listing page shows them as icons and `sameAs`.
- `templates/astro/dump-cities.mjs`: Gate 5, run in the site folder. `node dump-cities.mjs [05-zip-county.json] ../05-cities.json` writes the city structure as the site builds it (folds and town pages included) for `make_city_packets.py`; the ZIP-to-county JSON is optional, without it the CSV's `county` column is used and the script says so.
- `scripts/make_city_packets.py`, `scripts/city-copy-instructions.md`, `scripts/check_city_copy.py`, `scripts/clean_city_copy.py`: Gate 5 city copy. Place-first packets from the site's own city structure (what the trade leans toward, the places the listings name, optional `--city-facts`), small-town pages included with a 120-word floor (`--niche` and `--state` print the `directory:` line every batch opens with), the general rules, the checker (numbers, repeats, internal wording, tallies in disguise with the niche's own nouns; 2 to 6 FAQs on a town page; shared sentences and openings tallied across every written batch, only the checked batch's cities fail, the full check names the batches to rerun) and the mechanical cleanup.
- `templates/astro/preview-site.command` and `preview-site.bat`: the default way to look at a build. Double-click in `site/`; serves `dist/` with `astro preview --open`.
- `scripts/make_local_preview.py`: optional. Writes `output/<slug>/preview/`, a copy of the built site with relative paths and the stylesheet inside each page, for sending to someone who will open it from disk. Never for deploying.
- `scripts/mail_worker.py`: after launch. `keys --slug <slug>` prints the Terminal command the member runs to save the Anthropic key (`save-key anthropic`: asks for the key after it starts, hidden, tests it, saves it to the keychain or `~/.directory-blueprint/secrets.json`; never run by Claude); `check` says whether the key and the wrangler login work; `setup --slug <slug> --review-to <email>` copies `templates/worker/`, fills `wrangler.jsonc` from `site.json`, writes `listings.json`, creates the KV namespace, sets the secrets, deploys, records `WORKER_URL` and posts one test claim; `deploy` after a listings change; `wire-form` points `contact.formEndpoint` at the worker's `/claim`.
- `scripts/mail_inbox.py`: the worker's review queue from Claude Code: `--slug <slug>` lists open items with their drafts; `--send <id> [--text-file reply.txt]`, `--ignore <id>`, `--retriage <id>`. The key comes from the secret store, never printed.
- `scripts/make_worker_listings.py`: writes the compact `listings.json` the worker matches senders against (slug, name, city, phone digits, website host, rating, reviews, featured); `mail_worker.py` runs it at setup and deploy.
- `scripts/check_live.py`: Gate 6. Reads a deployed directory from the outside: home page, a 404 for an unknown address, robots.txt, sitemap count, indexable samples, `noindex` on conversion pages, the pages.dev header, and no example featured card.
- `scripts/lint_copy.py`: Gate 5 copy gate. `python3 scripts/lint_copy.py output/<slug>/site/src/data/city-copy.json --niche "<niche plural>" --city-sizes output/<slug>/05-city-sizes.json` (the size classes from page-types, town pages at 120 words and 2 to 6 FAQs), also built `dist/` pages, `.astro` and `.md` files with `--min-words` / `--max-words`. Reads `scripts/copy-bans.txt` on top of the skill's list.
